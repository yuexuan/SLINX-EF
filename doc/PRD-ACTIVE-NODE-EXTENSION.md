## 现状与关键约束

1. **主题已经存在**：`web/src/composable/theme.ts` 保存暗/亮状态，`web/src/view/Footer.vue` 实现切换并写入 localStorage，`web/src/asset/css/main.css` 有暗/亮变量。此次只迁移入口到**主内容区域顶部 Header 右侧**，复用现有逻辑和样式，不重新开发主题设置，也不保留重复的页底入口。
2. **上游代理已有基础支持**：`database.Endpoint`、`api/endpoint.go` 和 `core/config.go` 已支持 WireGuard、SOCKS5、HTTP CONNECT；SOCKS/HTTP 生成 sing-box `outbounds`，WireGuard 生成 `endpoints`。应沿用原有 ID、数据和路由绑定，避免重建第二套节点表或破坏旧配置。
3. **现有路由与故障语义**：`endpoint/widget/Route.vue` 可关联入站；禁用节点后保留绑定但阻断，删除后路由转为 block，避免静默直连。扩展所有新协议时沿用此原则。
4. **现有检测是服务器出口检测**：`service/ip.go`、`service/unlock.go` 使用默认 HTTP Client；`service/back_route.go` 使用服务器侧 MTR。尚不支持指定出站，不能把服务器检测结果写成某个 ISP 节点的结果。
5. **订阅导出与出站导出不同**：`internal/sub/sub.go` 基于用户及入站提供 URI、Clash、Surge、sing-box 客户端配置；它描述的是**客户端连接香港入口**，不应泄漏服务器持有的 ISP/SSH 凭据。新增的**直接导出代理出口**应为独立能力。
6. 不改造 SSPanel 的用户/套餐模式，不增加审批、授权体系或冗余架构。不无故改变当前 Release、安装器和已有服务。真实供应商账号未提供时，只能验收生成和连接失败行为，不能声称出口 IP 已通过真实连通性检测。

| 协议/类型 | 当前状态 | 本期目标 |
| --- | --- | --- |

## P3 — 动态住宅/ISP 代理管理

**任务**
- **动态代理不是新传输协议**，而是在 SOCKS5/HTTP 等基础出站上叠加供应商分配策略。
- 为节点提供三种模式：
  1. 固定网关：固定 Host/Port/认证；
  2. 会话网关：支持 Session ID、粘性会话、有效期及供应商账号模板参数；
  3. API 轮换网关：供应商换 IP 接口、请求方法、必要请求参数、返回字段映射。
- 支持手动切换及有明确失效证据时的按需更新；换 IP 后正确刷新代理连接/会话，并记录前后实际出口 IP。可选定时检查，不以高频轮询为默认。
- 连接超时、认证过期、供应商明确失效等需区分处理；目标站 HTTP 403/429 不得直接当作出口代理失效。

**验收**
- 至少一类真实会话网关与一类有 API 的轮换供应商能够在配置后执行换 IP，前后公网出口可验证（没有真实账号时明确标记未实测）。
- 旧 ISP 静态出口无需填动态配置即可继续使用。
- 失败提示能区分供应商接口错误、认证失败、出口不可达和目标站限制。

P3 执行记录：已实现 fixed/session/api 策略、会话模板/有效期、API 请求与字段映射、手动及连续传输失败按需轮换，记录前后实测 IP。403/429 不作为代理失效。真实供应商凭据未提供，供应商验收 NOT VERIFIED；受控 API 分配、会话 ID 变化、核心连接刷新与前后实际公网查询 PASS；测试网关 IP 未改变，未宣称真实供应商换 IP 成功。按需轮换额外确认直连网关 TCP 不可达；经中继链的歧义故障不自动轮换。

## P4 — 指定节点的 IP、AI、流媒体检测
